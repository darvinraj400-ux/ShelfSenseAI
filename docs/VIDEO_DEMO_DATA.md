## DO NOT CLICK (destructive / slow — for the live video)

- **Do NOT click "Apply Recommendation"** on product 6001 — it changes the real price and writes PriceHistory/a decision.
- **Do NOT click "Dismiss"** on the main product (optional, but changes the state).
- **Do NOT delete / edit products**, record sales, or receive/adjust stock during the recording.
- **Do NOT run** `flask market-data refresh` (PriceCatcher rebuild is heavy).
- **Do NOT open `/product/<id>` as owner more than needed before recording** — a page view lazily creates a PENDING decision snapshot (that is normal Phase 8 behaviour and is fine to show once).

## Performance note (important for recording)

- `/market-data` and `/pricing-dashboard` are fast after warm-up. Visit them once before recording.
- `/dashboard` and `/product/6001` currently take **~15–26 s** on this machine because the
  existing `get_dashboard_metrics()` and pricing engine load **national** observations
  (5k–25k rows per matched item) instead of the shop's Segamat slice. This is a
  pre-existing application characteristic (same on the original Demo Retail Shop),
  **not** caused by this seed. Recommended mitigation is a small application change
  (pass the shop's geography through those read paths), to be approved separately.
  For a safe recording, pre-load the Dashboard and product page, or record those two
  scenes from a prepared/warmed tab.

## Reset

```bash
./venv/Scripts/python.exe seed_video_demo.py          # create/refresh (idempotent)
./venv/Scripts/python.exe seed_video_demo.py --clear  # remove only video-demo data
./venv/Scripts/python.exe clear_video_demo.py         # same clear, standalone
```

The seed is idempotent: re-running it clears the video shop first and recreates it,
so you can restore a pristine state (no decisions) at any time.
